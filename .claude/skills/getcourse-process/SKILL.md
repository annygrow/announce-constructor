# GetCourse: рассылки + процессы (браузерная автосборка)

Скилл автоматизирует то, что в админке GC делается мышкой и долго: создание пачки рассылок и сборку процесса (`/pl/tasks/mission/`) с блоками, задержками и стрелками. Всё через **Playwright MCP** + прямые JS-вызовы (DOM + `$('#flowchart').flowchartPlugin('instance')`), потому что canvas-конструктор не принимает синтетический drag&drop.

## Когда использовать

- «создай 10 рассылок тема 1/текст 1 … и собери из них процесс по пользователям с паузами 1 час»
- «сделай цепочку писем / автоворонку в процессах GC»
- «массово нагенери рассылки», «свяжи блоки в процессе стрелками»

Если задача — встроить GC API в серверный код (вебхук, форма), это другой скилл — `getcourse-api`. Этот скилл про **работу в админке через браузер**.

## Предусловия

1. **Доступ к аккаунту** (логин/пароль). Логин: `/cms/system/login`, поля `Введите почту`/`Введите пароль` → кнопка `Войти на платформу`. После — закрыть плашку cookies (кнопка `Ok`), иначе перехватывает клики.
2. **Playwright MCP** подключён (`mcp__playwright__browser_*`). Тяжёлую работу гнать через `browser_run_code_unsafe` (доступен `page`) — это на порядок быстрее пошаговых кликов.
3. У GC глобально доступен `$` (jQuery). Внутренний API конструктора: `$('#flowchart').flowchartPlugin('instance')`.

## ВАЖНО: безопасность (по умолчанию ничего не запускать)

- Рассылки оставлять **черновиками**: получатель «Никому» (по умолчанию), кнопку **«Готово к отправке»** (`button[name=ready]`) НЕ нажимать.
- Процесс оставлять **неактивным**: «Массовое создание задач» = Отключено, **не** жать «Активизировать», галку «Одобрено» не ставить.
- Подтверждать у пользователя до старта: какой аккаунт, сколько писем, структуру веток, тексты.

## Ключевые факты GC (проверено)

- Транспорт рассылки (`#transport`): `email`, `sms`, `ticket` (Telegram), `fb_messenger`, `vk`, `chatium` (Приложение), `whatsapp` (WhatsApp/Max/WABA), `max` (MAX). **Telegram = `ticket`**, а не "telegram" или "tg".
- Категория рассылок — обязательное поле. Значения select: `0` = «Общие рассылки», `-1` = «Уведомления».
- Тип объекта процесса: `41` = Пользователи, `42` = Заказы, `58` = Покупки, `27` = Звонки.
- `save-scripts` сохраняет у блоков **только `id` + `coord`** (раскладку). Связи пишутся отдельно (`create-connection`).
- Один выход блока (`-success`) допускает **одну** исходящую связь. Для нескольких веток из блока — увеличить число выходов (`resultsCount`), доп. выходы получают uuid `<id>-result1`, `<id>-result2`, …

## Порядок работы

1. Залогиниться, закрыть cookies.
2. **Рассылки** — для каждой: `/notifications/control/mailings/new` (без `/pl/`!) → задать поля → «Создать рассылку» → на странице редактора задать тему/текст → **для ТГ (`ticket`) и MAX (`max`) обязательно выставить «Любой бот» (id=0) в select до сохранения** → «Сохранить». Делать пачкой в одном `browser_run_code_unsafe`. Запоминать ID (из URL `update/id/<ID>`).
3. **Процесс** — `/pl/tasks/mission/create` → название + тип объекта → «Создать». Из URL взять `missionId`.
4. **Блоки** — на `/pl/tasks/mission/process?id=<missionId>` добавлять через `.btn-add-block[data-block-type=...]`, настраивать в модалке, сохранять. Пачкой.
5. **Раскладка** — расставить блоки в колонки (мутировать `inst.blocks[].coord` → `inst.saveScripts(missionId)`).
6. **Связи** — `inst.instance.connect(...)` по парам src→dst (см. сниппеты). Для веток из старта — сначала `resultsCount`.
7. **Проверка** — `POST /pl/tasks/mission/flowchart-data?id=<missionId>`: сверить число блоков/связей и `issetScriptErrors=false`.

Готовые функции и точные селекторы — в `snippets/gc_process_automation.js`. Подробная карта полей форм и модалок — в `references/selectors.md`.

## HTML-письма по дизайн-шаблону (массовая сборка из файла)

Когда дают файл с текстами писем + HTML-шаблон дизайна и просят «собрать рассылки по шаблону»:

1. **Парсинг источника** в структуру `[{header, subject, fromName, ctas[], body[]}]`. Markdown из Google Docs приходит с экранированием (`\!`, `\.`, `{first\_name}`) и картинками base64 в конце как `[imageN]: <data:...>` + инлайн `![][imageN]` — выкидывать дефиниции и маркеры, бэкслеши снимать (`s.replace(/\\(.)/g,'$1')`). **Эмфазу `**`/`*` в теле НЕ срезать** — нужна для `<strong>/<em>`. Грабли: тема бывает в 2 строки (хвост утекает в `body[0]`); у части писем темы нет (задать); пустые письма-заглушки (только заголовок) — пропускать.
2. **Рендер HTML** из дизайн-шаблона: вытащить из шаблона токены (лого-URL, цвета, шрифты, кнопка, футер) и собрать на чистых **inline-стилях** (email-клиенты + summernote режут `<style>`/классы — поэтому всё инлайном; `@media`-адаптив теряется, десктоп-вид на `max-width` остаётся). Карточки (серая/синяя/белая), жёлтая CTA-кнопка, тёмный футер. `{first_name}` оставлять как есть (GC-переменная). Инлайн `[текст]` в теле → CTA-кнопка.
3. **Проверка вёрстки**: GetCourse summernote **сохраняет табличный HTML без потерь** (добавляет только `<tbody>`). Ставить через `$('#Mailing_content').summernote('code', html)`; после сейва свериться `$('#Mailing_content').val()` (число `<table`, цвета, текст кнопки).
4. **Создание** — пачкой через форму (см. `createHtmlMailings` в сниппетах). Все черновики.

Готовый пайплайн-пример (Node-скрипты) — в `references/html_email_pipeline.md`: `parse_letters.js` → `build_mailings.js` → `gen_runfile.js`. Большие данные писем встраивать в файл и запускать `browser_run_code_unsafe({filename})` (в этом sandbox НЕТ `require`/`fs` — только `page`; данные эмитить в сам файл). Вывод раздувается эхом кода — возвращать компактный `results`, парсить из сохранённого tool-result.

## Типовые грабли

- Рефы DOM (`e66` и т.п.) в снапшотах **сдвигаются** после каждого перехода — не переиспользовать между навигациями. В JS-сниппетах адресоваться по `id`/`name`/тексту.
- Кнопка «Сохранить» в модалке часто **без** `type=submit` (дефолтный submit у `<button>`), и в тексте есть иконка-глиф. Искать по `textContent.includes('Сохранить')` среди видимых `form button`, исключая «Готово».
- `inst.scriptModalEl` — это **jQuery-объект**; DOM-узел брать `$(inst.scriptModalEl)[0]`.
- Поле «Рассылка» в блоке — select2 на скрытом инпуте: задавать `$('#addmailingmessageoperation-mailing_id').select2('data',{id,text})`.
- Связь ставится так: `source` = объект эндпоинта `jp.getEndpoint('<src>-success')`, `target` = DOM-элемент `document.getElementById('fwb<dst>')`. Вариант через `uuids:['<src>-success','<dst>-target']` ненадёжен.
- `inst.saveScripts` показывает `alert('Сохранено')` — перед вызовом подменить `window.alert = ()=>{}`.
